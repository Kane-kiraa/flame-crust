# របាយការណ៍វិភាគគម្រោងលម្អិត "Flame & Crust Pizza" (Full System Analysis)

របាយការណ៍នេះធ្វើការវិភាគស៊ីជម្រៅទៅលើលក្ខណៈពិសេសដែលប្រព័ន្ធ **មានស្រាប់ (Current Features)** និងចំណុចខ្វះខាតដែល **ប្រព័ន្ធខ្វះ ឬគួរបន្ថែម (Missing Features & Shortcomings)** ទាំងផ្នែក Business Logic, Architecture, និង Database ដើម្បីឱ្យគម្រោងនេះអាចពង្រីកខ្លួនទៅជាប្រព័ន្ធខ្នាតធំ (Enterprise Level) បាន។

---

## ផ្នែកទី ១៖ អ្វីដែលប្រព័ន្ធមានស្រាប់ (Current System Capabilities)

ទោះបីជាគម្រោងនេះនៅមានចំណុចខ្វះខាត ប៉ុន្តែវាត្រូវបានសាងសង់ឡើងជាមួយនឹងបច្ចេកវិទ្យាទំនើប និងមានមុខងារល្អៗជាច្រើន៖

### ១.១ បច្ចេកវិទ្យាទំនើប (Modern Tech Stack)
- **Frontend ដ៏ស្រស់ស្អាត និងលឿន:** ប្រើប្រាស់ React 19 (Vite) គួបផ្សំជាមួយ Tailwind CSS v4 និង Shadcn UI ធ្វើឱ្យការរចនាមានភាពទាក់ទាញ (Premium UI)។ វាមានចលនា (Animations) យ៉ាងរលូនដោយប្រើ `framer-motion`។
- **Backend ដ៏រឹងមាំ:** ប្រើប្រាស់ Java 21 (Spring Boot) ជាមួយ MySQL 8.4 ដែលធានាបាននូវសុវត្ថិភាព និងល្បឿនក្នុងការទាញយកទិន្នន័យ (Robustness)។
- **PWA (Progressive Web App):** អតិថិជន និងអ្នកដឹកជញ្ជូនអាច Install វេបសាយនេះជា App ចូលទៅក្នុងទូរស័ព្ទដៃរបស់ពួកគេបានយ៉ាងងាយស្រួល។

### ១.២ កម្មវិធី ៤ ក្នុងប្រព័ន្ធតែមួយ (Unified Ecosystem)
ប្រព័ន្ធនេះមាន Portals ចំនួន ៤ ដាច់ដោយឡែកពីគ្នា ដែលធ្វើការស៊ីសង្វាក់គ្នា (Sync) យ៉ាងល្អ៖
1. **Customer Storefront:** កន្លែងអតិថិជនមើល Menu, ដាក់ចូលកន្ត្រក, បញ្ចូលលេខកូដបញ្ចុះតម្លៃ (Coupon), និង Checkout។
2. **Admin Dashboard:** កន្លែងម្ចាស់ហាងគ្រប់គ្រងទិន្នន័យទាំង ១៨ តារាង (Products, Orders, Customers, Users...) និងមើលរបាយការណ៍។
3. **Driver App:** កន្លែងអ្នកដឹកជញ្ជូន ទទួលការងារ និង Update ទីតាំងទៅកាន់អតិថិជន។
4. **Kitchen Dashboard (KDS):** ក្តារ Kanban អេក្រង់ធំសម្រាប់ចុងភៅ មើលការកម្ម៉ង់ដែលចូលមកភ្លាមៗ និងចុចផ្លាស់ប្តូរស្ថានភាពពី (Confirm -> Prepare -> Ready)។

### ១.៣ មុខងារស្នូលសំខាន់ៗ (Core Features)
- **ប្រព័ន្ធទូទាត់ប្រាក់ចម្រុះ:** គាំទ្រការបង់លុយសុទ្ធ (Cash) និងការស្កេនទូទាត់ប្រាក់តាមធនាគារ (ABA KHQR / Bakong) ដោយស្វ័យប្រវត្តិ។
- **ប្រព័ន្ធគណនីសម្បូរបែប:** អនុញ្ញាតឱ្យចូលគណនី (Login) តាមរយៈ Email/Password, ប្រើលេខកូដ OTP បណ្ដោះអាសន្ន, ឬ Login តាមរយៈ Google Account យ៉ាងងាយស្រួល។
- **ការកត់ត្រាសុវត្ថិភាព (Audit Logs):** រាល់សកម្មភាពកែប្រែទិន្នន័យរបស់ Admin ឬបុគ្គលិក (Create, Update, Delete) ត្រូវបានកត់ត្រាទុកក្នុង `audit_logs` ទាំងអស់ ដើម្បីងាយស្រួលផ្ទៀងផ្ទាត់ពេលមានបញ្ហា។

## ផ្នែកទី ២៖ អ្វីដែលប្រព័ន្ធខ្វះខាត និងទាមទារការជួសជុល (Shortcomings & Missing Features)

ដើម្បីឱ្យប្រព័ន្ធនេះក្លាយជាស្តង់ដារហាងធំៗ (ដូចជា Pizza Company ជាដើម) ខាងក្រោមនេះគឺជាចំណុចខ្សោយ និងមុខងារដែលនៅខ្វះ ដែលត្រូវយកចិត្តទុកដាក់បំពាក់បន្ថែម៖

### ២.១ បញ្ហាលើ Business Logic និងមុខងារ (Missing Business Features)
1. **កង្វះការគ្រប់គ្រងច្រើនសាខា (No Multi-Branch / Franchise Support):**
   - ✖️ *បញ្ហា:* Database បច្ចុប្បន្នសន្មត់ថាមានហាងតែមួយគត់។ មិនមានតារាង `branches` ទេ។
   - 💡 *ដំណោះស្រាយ:* បើហាង Flame & Crust បើកសាខាទី២ នៅទួលគោក ប្រព័ន្ធនេះត្រូវសរសេររចនាសម្ព័ន្ធ Database ឡើងវិញទាំងស្រុង ដើម្បីបំបែក Order, ឃ្លាំងទំនិញ, និងបុគ្គលិកតាមសាខានីមួយៗ។
2. **កង្វះប្រព័ន្ធសន្សំពិន្ទុអតិថិជន (No Loyalty Program & Wallet):**
   - ✖️ *បញ្ហា:* មិនទាន់មានប្រព័ន្ធកាតសមាជិក (VIP/Gold/Silver) សន្សំពិន្ទុ (Points) ដើម្បីប្ដូរយករង្វាន់ ឬកាបូបលុយ (Digital Wallet) ក្នុង App នៅឡើយទេ។
3. **កង្វះការផ្តល់ប្រាក់លើកទឹកចិត្តអ្នកដឹក (No Driver Tipping System):**
   - ✖️ *បញ្ហា:* អតិថិជនមិនអាច Tip លុយឱ្យអ្នកដឹកជញ្ជូនតាមរយៈការកាត់កាត ឬ KHQR បានទេ (ទាល់តែឱ្យលុយសុទ្ធក្រៅ)។
4. **កង្វះការកែប្រែការកម្ម៉ង់ (No Order Modification by Customer):**
   - ✖️ *បញ្ហា:* ពេលអតិថិជនចុច Checkout រួច បើចង់ប្ដូរទំហំភីហ្សាពីតូចទៅធំ អតិថិជនមិនអាចកែប្រែក្នុង App ខ្លួនឯងបានទេ (ទាល់តែតេទៅហាងឱ្យ Admin កែឱ្យ ឬលុបចោលកម្ម៉ង់ថ្មី)។
5. **កង្វះប្រព័ន្ធបង្វិលប្រាក់ (No Automated Refund Flow):**
   - ✖️ *បញ្ហា:* បើអតិថិជនទូទាត់លុយតាម KHQR រួចរាល់ ហើយហាងចុច `CANCELLED` លុយនោះមិនមានប្រព័ន្ធ Refund ត្រលប់ទៅវិញដោយស្វ័យប្រវត្តិទេ (ទាមទារការវេរលុយសងដោយដៃ)។

### ២.២ បញ្ហាលើបច្ចេកវិទ្យា និង Architecture (Technical Shortcomings)
1. **គ្មាន WebSockets / គ្មាន Push Notifications (No Real-Time Server Push):**
   - ✖️ *បញ្ហា:* ការ Update ទីតាំង Driver ទៅកាន់អតិថិជន ប្រើប្រាស់បច្ចេកទេស Polling (Frontend ទាមទារ Data រៀងរាល់ ១០ ឬ ៣០ វិនាទី)។ នេះធ្វើឱ្យ Server ធ្វើការធ្ងន់បើមានអ្នកប្រើប្រាស់ច្រើន (High Load) ព្រមទាំងគ្មានការរោទិ៍សំឡេង (Push Notification) ពេលហាងទទួលបាន Order ថ្មី ពេលបិទអេក្រង់ទូរស័ព្ទ។
   - 💡 *ដំណោះស្រាយ:* គួរប្រើ WebSockets (Spring Boot WebSocket / Socket.io) ឬ Firebase Cloud Messaging (FCM) សម្រាប់ Notifications ពិតប្រាកដ។
2. **គ្មានការគ្រប់គ្រងស្តុក (Missing Inventory Tracking):**
   - ✖️ *បញ្ហា:* Database `products` អត់មាន field `stock_quantity`។ គ្មានការកាត់ស្តុកវត្ថុធាតុដើមនៅពេលលក់ចេញ។ បើអស់ទំនិញ អតិថិជននៅតែអាចកម្ម៉ង់បាន រហូតទាល់តែ Admin ទៅបិទ Manual។
3. **បញ្ហាភាពយឺតយ៉ាវនៃរបាយការណ៍ (Reporting Scalability Risks):**
   - ✖️ *បញ្ហា:* ការទាញយកទិន្នន័យចំណូលប្រចាំខែ (Dashboard Analytics) ធ្វើឡើងដោយ Query ផ្ទាល់ទៅលើតារាង `orders`។ បើ Orders កើនឡើងដល់រាប់លាន របាយការណ៍ Dashboard និងដើរយឺតខ្លាំង។
   - 💡 *ដំណោះស្រាយ:* គួរមានការរៀបចំ Data Warehousing ឬ Materialized Views សម្រាប់តែទាញយករបាយការណ៍។

### ២.៣ ចំណុចខ្សោយលម្អិតនៅក្នុង Database (Database Specific Deficiencies)
1. **Payment Relationship (1-to-1 Bottleneck):**
   - តារាង `payments` មាន Relation 1-to-1 ជាមួយ `orders` (`order_id UNIQUE`)។ នេះមានន័យថា ១ Order អាចមាន Payment Record តែមួយគត់។ បើ Payment ទី១ គាំងអត់ដើរ ប្រព័ន្ធមិនអាចបង្កើត Payment ទី២ (ឧទាហរណ៍៖ អតិថិជនប្តូរចិត្តយកចុចទូទាត់តាមកាតជំនួសវិញ) សម្រាប់ Order ដដែលនោះបានទេ។
2. **កង្វះការតាមដានល្បឿនចម្អិន (No Kitchen Performance Timestamps):**
   - តារាង `orders` មិនមាន Columns `prepared_at` ឬ `ready_at` ដាច់ដោយឡែកឡើយ។ ម្ចាស់ហាងមិនអាចទាញរបាយការណ៍វាស់ស្ទង់ថា "ជាមធ្យមចុងភៅចាយពេលប៉ុន្មាននាទី ដើម្បីធ្វើភីហ្សាមួយ" នោះទេ។
3. **កង្វះប្រវត្តិអ្នកដឹកជញ្ជូន (Missing Driver Historical Locations):**
   - ទីតាំងអ្នកដឹកជញ្ជូន មិនមានការកត់ត្រាទុកក្នុង `driver_locations_history` ទេ។ យើងអត់អាច Playback មើលឡើងវិញបានទេថាម្សិលមិញ អ្នកដឹកជញ្ជូនរូបនេះ ជិះទៅផ្លូវណាខ្លះ។
4. **កង្វះការគាំទ្រពហុភាសា (Single Language Content):**
   - `products.name` និង `products.description` មានតែមួយ Column ប៉ុណ្ណោះ ដែលមានន័យថា App នេះអត់អាចមានការប្ដូរភាសាខ្មែរ/អង់គ្លេស សម្រាប់មុខម្ហូប និងការពិពណ៌នាបានទេ។
5. **សុវត្ថិភាពការរក្សាទុកកាត (Cart Integrity Issues):**
   - តារាង `cart_items` អត់មានពិនិត្យឡើងវិញនូវតម្លៃទំនិញ (Price Snapshot) ទេ។ បើទំនិញដកចេញពី Menu ភ្លាមៗ ឬឡើងថ្លៃ ខណៈពេលអតិថិជនកំពុងបើកកន្ត្រក វាអាចបង្កជាបញ្ហាទិន្នន័យ (Data Consistency)។

## សេចក្តីសន្និដ្ឋានរួម (Conclusion)

គម្រោង **Flame & Crust Pizza** នេះត្រូវបានសាងសង់ឡើងបានយ៉ាងល្អឥតខ្ចោះ សម្រាប់អាជីវកម្មខ្នាតតូច ទៅមធ្យម (SMBs) ដែលមានសាខាតែមួយ។ ផ្ទាំង UI មានភាពស្រស់ស្អាត ទាក់ទាញ និងងាយស្រួលប្រើប្រាស់។

ប៉ុន្តែ ប្រសិនបើអាជីវកម្មនេះចង់ពង្រីកទៅជា **Enterprise (មានសាខាច្រើន មានអតិថិជនប្រើប្រាស់រាប់ម៉ឺននាក់)** គម្រោងនេះត្រូវតែធ្វើការ **Refactoring (សរសេររចនាសម្ព័ន្ធ Core កម្រិតទាបឡើងវិញ)** ជាបន្ទាន់ ជាពិសេសទៅលើចំណុច៖
1. **Inventory Management** (កាត់ស្តុកដោយស្វ័យប្រវត្តិ)
2. **WebSockets** (បញ្ជូនដំណឹង Real-time មិនស៊ី Data)
3. **Multi-Store Architecture** (បំបែកទិន្នន័យតាមសាខា)
4. **Robust Payment Retry Flow** (អនុញ្ញាតឱ្យទូទាត់សងវិញពេលបរាជ័យ)
